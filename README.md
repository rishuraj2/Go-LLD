# Go-LLD

A collection of **Low-Level Design (LLD)** implementations in **Go**, built to understand and practice object-oriented design, design patterns, SOLID principles, and real-world system modeling.

This repository contains solutions to popular LLD interview problems with a strong focus on writing clean, extensible, and production-quality code rather than just making the program work.

---

## 🎯 Goals

- Practice Low-Level Design through hands-on coding.
- Learn to identify entities, relationships, and responsibilities.
- Apply SOLID principles and Go best practices.
- Implement common Design Patterns where they naturally fit.
- Build scalable and maintainable solutions.
- Create a reference repository for interview preparation.

## 🏗️ Repository Structure

```
go-lld/
│
├── tic-tac-toe/
├── parking-lot/
├── chess/
├── snake-and-ladder/
├── ...
│
├── pkg/                 # Shared utilities (if any)
├── docs/                # UML diagrams, notes, explanations
└── README.md
```

Each problem is self-contained and includes:

- Problem Statement
- Requirements
- Assumptions
- Class/Object Design
- UML/Class Diagram (where applicable)
- Design Patterns Used
- Source Code
- Sample Execution
- Possible Extensions

## 🚀 Getting Started

Clone the repository:

```bash
git clone https://github.com/<your-username>/go-lld.git
```

Navigate to any design problem:

```bash
cd parking-lot
```

Run:

```bash
go run .
```

or

```bash
go test ./...
```

## 📖 Learning Approach

Each solution follows a structured workflow:

1. Understand the problem.
2. Identify entities and relationships.
3. Define responsibilities.
4. Design interfaces.
5. Apply suitable design patterns.
6. Implement incrementally.
7. Refactor for extensibility.
8. Add tests and documentation.

The objective is to think like a software engineer designing a production-ready system rather than solving a coding exercise.
